home.widgets

Writing a widget

A widget is one script that returns a description, never pixels. Home owns drawing and timing, so a widget cannot animate, flash the panel or keep the CPU awake. Proposed language: Lua, because KOReader keeps its data as Lua tables and a sandboxed Lua is tiny. QuickJS would work the same way; this is an open decision.

The Continue reading widget, whole

-- ~/.local/share/glassine/widgets/reading/widget.lua
return {
  name    = "Continue reading",
  icon    = "menu_book",
  sizes   = { "wide", "half" },              -- first is the default
  reads   = { "~/.config/koreader/history.lua" },
  refresh = { on_change = true },            -- or { every = "1h" }, never under 15 min

  props   = {},                              -- settings this widget keeps; none here

  render = function(ctx, props)
    local last = ctx.load_lua("~/.config/koreader/history.lua")[1]
    if not last then return { ui.text("Nothing read yet") } end
    local doc  = ctx.load_lua(ctx.sidecar(last.file))   -- KOReader’s .sdr metadata
    return {
      ui.image{ src = "cover:" .. last.file, w = 64, h = 96, side = "left",
                alt = "Cover of " .. doc.doc_props.title },   -- a slot, not pixels
      ui.title(doc.doc_props.title),
      ui.text(doc.doc_props.authors),
      ui.progress(doc.percent_finished),
      ui.button("Continue", "play_arrow", ui.open("koreader", last.file)),
      ui.meta("Read " .. ctx.ago(last.time)),
    }
  end,
}

Settings: widget.edit.lua

-- …/widgets/app-category/widget.edit.lua  (Home's own App category settings)
-- Same ui, same sandbox, same lifecycle as widget.lua. Home runs it when you tap
-- the widget's settings button and again after every change.
return {
  render = function(ctx, props)
    local rows = {}
    for _, c in ipairs(ctx.apps.categories()) do
      rows[#rows + 1] = { c.name, c.count .. " apps",
                          selected = (c.name == props.category),
                          action   = ui.set{ category = c.name } }
    end
    return { ui.title("Show apps from"), ui.list(rows) }
  end,
}
-- widget.lua declares the defaults:  props = { category = "Games" }
-- and gets them back as             render = function(ctx, props) … end

The seven primitives

ui.title(text)One line, bold. At most one per widget.
ui.text(text, {soft=true})One line; soft draws it in the secondary grey.
ui.progress(0…1, label)A bar with its number. No animation.
ui.list({ {label, meta}, … })Up to 4 rows; more are cut, not scrolled.
ui.button(label, icon, action)At most 2. Actions: ui.open(app, file?), ui.settings(page). Nothing else can run.
ui.meta(text)The small line at the bottom: when, from where.
ui.image{src, w, h, side, fit, alt}A slot of a fixed size that Home fills later. side = "left" or "right" pins it beside the text; without side it runs full width at height h. fit: cover (default) or contain. At most 2.

Rules Home enforces

SandboxLua 5.4 with no os, io, require or load. A widget reads only the paths it lists in reads, through ctx.read and ctx.load_lua (which evaluates a data file in an empty environment). No network unless the manifest lists hosts in net, shown when you add it.
RefreshHome runs render, never the widget itself: when a listed file changes, on its every interval (15 min at least), and once when Home appears. Results are compared; only a widget whose output changed is redrawn, as one partial refresh of its own card, batched with any others.
Time limitrender has 200 ms and 4 MB. Over that, or on an error, Home keeps the last good output and the meta line says so. Three failures in a row pause the widget until you open the gallery.
SettingsA widget with settings ships widget.edit.lua next to widget.lua: the same primitives, sandbox and limits, run the same way. Both render functions get (ctx, props). props start from the manifest’s defaults and are kept per widget, so two copies can differ. In edit scripts, list rows and buttons may carry ui.set{…}, which changes props; Home then re-runs both scripts. selected = true marks a row as the current choice.
Imagesrender never touches pixels: it returns a slot with a source and a size, so Home lays the card out at once and nothing moves later. Home then loads, scales to the slot, turns it grey and dithers it with the E-ink dithering setting in a low-priority worker, outside the 200 ms. It starts right after render, even while Home is hidden, so Home usually appears finished; otherwise the slot shows a dashed frame with its alt text and fills with one partial refresh of that rectangle only. Results are cached by source, its date or ETag, slot size and dithering, so an unchanged slot never loads twice. Sources: file: (inside reads), cover: (an ebook’s cover, via the thumbnailer), icon: (an app’s icon), https: (only hosts listed in net). Over 20 MB, or broken: the frame and alt text stay.
LookWidgets have no colours, fonts or layout of their own. Home draws the seven primitives in the current voice at the card’s size: half is 2 columns, wide is 4, always one row of the page grid.
PagesA page is 4 columns × 5 rows in portrait, two lanes of 4 × 3 in landscape. Widgets flow in order and a half fills the first free half on its page; one that doesn’t fit goes to the next lane or page. Favourite apps, All apps and App category are built into Home, drawn natively: 1 to 5 rows, each with its own pager. All apps is always on Home; App category can be added as often as you like.
Where they liveBuilt-in widgets ship with glassine-home. Apps can bring one in their package under /usr/share/glassine/widgets. Your own go in ~/.local/share/glassine/widgets, one folder each; Home picks up a new folder without a restart.
