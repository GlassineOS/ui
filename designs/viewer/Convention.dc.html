A board names its states

Today a board that has several states draws its own row of buttons to switch between them, inside its own pixels. With $states the board says which states it has, and the viewer shows them: on the tile, in the filmstrip, in the matrix, in the flow, and in the review.

Today

OffOnScanningConnectedWindow: fullcolumn
  • The buttons are part of the board, so they are in every screenshot and every review image.
  • Each design draws them differently; the viewer cannot see them.
  • An agent reaches a state only by naming clicks (--click).

With $states

  • The board shows only the screen. The viewer draws the state switch.
  • States are addressable: view.html?board=…&state=scanning.
  • tools/boards shot FILE --state scanning; the checks render every state.

In the board file

<script type="text/x-dc" data-dc-script data-props='{
  "$preview": { "width": 760, "height": 1140 },
  "$states": [
    { "id": "off",       "name": "Off",       "props": { "bt": "off" } },
    { "id": "on",        "name": "On",        "props": { "bt": "on" } },
    { "id": "scanning",  "name": "Scanning",  "props": { "bt": "scan" } },
    { "id": "connected", "name": "Connected", "props": { "bt": "on", "paired": "Keyboard K380" },
      "from": [{ "state": "scanning", "label": "Pair" }] }
  ],
  "bt": { "editor": "enum", "options": ["off", "on", "scan"], "default": "off" },
  "paired": { "editor": "text", "default": "" }
}'>

Only props

A state is a set of the board’s own props, nothing more. The logic does not change; a board without $states works as before.

Arrows for the flow

Links between boards come from <a href>. A change of state inside one board has no link, so from names it, with the label on the arrow.

Checked

The check reads $states: an unknown prop or option, or a duplicate id, is an error. Every state renders in designs-check.
